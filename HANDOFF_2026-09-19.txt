3. Root-caused and partially fixed a REAL bug matching the user's live reports
   this session ("sometimes the client is stuck / getting a database-ish
   error", "sometimes getting sync error"):
   - ROOT CAUSE: `apiFetch` in BOTH apps/client-web/src/lib/apiClient.ts and
     apps/admin-web/src/lib/apiClient.ts called plain `fetch()` with NO
     timeout. Browser fetch() never times out on its own - if the LAN server
     is mid-restart, unreachable, or the Wi-Fi silently drops packets instead
     of resetting the connection, the request hangs FOREVER. Every caller
     (React Query queries, plain awaits) then just sits in an infinite
     loading state with no error ever firing - this is almost certainly what
     "the client gets stuck" and "sync error" refer to.
   - FIXED: both apiClient.ts files now wrap their fetch() in an
     AbortController with a 15-second timeout, throwing a clear "Couldn't
     reach the server..." Error on abort/network failure instead of hanging.
     (admin-web's `publishAppUpdate` deliberately was NOT given this timeout -
     it's a large file upload that can legitimately take longer than 15s.)
   - Both files typecheck clean after this change.
